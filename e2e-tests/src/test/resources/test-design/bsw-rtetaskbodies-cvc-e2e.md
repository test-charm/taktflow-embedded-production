# CVC RTE 任务体分派 (bsw_rtetaskbodies_cvc) E2E 测试设计

## 被测功能

**CVC 的 OSEK 任务体（生成自 DBC 的 BSW 可执行代码，S-OS-11）**

`firmware/ecu/cvc/cfg/Rte_TaskBodies_Cvc.c` 由 `tools/arxmlgen` 从
`gateway/taktflow_vehicle.dbc`（→ `TaktflowSystem.arxml` → `project.yaml`）生成，
文件头为 `GENERATED BY arxmlgen v1.0.0 -- DO NOT EDIT`。它定义六个 OSEK 任务体，
按 **S-OS-11**（优先级降序、同优先级按可运行实体表索引）分派 runnable，并复刻
`Rte_DispatchRunnables`（Rte.c:40-105）的 WdgM checkpoint 语义（每个唯一 seId 在
该组首个子实体后发一次 checkpoint）：

| 任务体 | 分派的 runnable | WdgM checkpoint（seId） |
|---|---|---|
| `Os_Task_Cvc_1ms` | `Can_MainFunction_Read` → `Can_MainFunction_Write` | 无 |
| `Os_Task_Cvc_10ms` | `Com_MainFunction_Rx` → `Swc_EStop` → `Swc_Pedal` → `Swc_VehicleState` → `Swc_Dashboard` → `Com_MainFunction_Tx` → `Can_MainFunction_BusOff` | 2（EStop）、0（Pedal）、1（VSM）、4（Dashboard） |
| `Os_Task_Cvc_50ms` | `Swc_Heartbeat_MainFunction` | 3（Heartbeat） |
| `Os_Task_Cvc_100ms` | 无 | 无 |
| `Os_Task_Cvc_5000ms` | 无 | 无 |
| `Os_Task_Cvc_Idle` | 先 `Cvc_Os_StartScheduleTables()`，再死循环 `Os_TaskMap_RunMappedFunctions(OS_TASK_CVC_IDLE)` | 无 |

覆盖链路：

```text
测试 API 注入（op=run task=1ms|10ms|50ms|100ms|5000ms|idle [idleIters=N]）
  → harness 链接 Rte_TaskBodies_Cvc.c，mock 全部外部依赖
       Os_TaskMap_RunMappedFunctions（记录 map:<任务ID>）
       SWC/BSW runnable（记录调用名）
       WdgM_CheckpointReached（记录 cp:<seId>，返回 E_OK）
       TerminateTask（计数，返回 E_OK）
       Cvc_Os_StartScheduleTables（计数，返回 E_OK）
  → 驱动任务体执行
  → 观测（harness 输出）：results[] 每操作 state 快照
       · callSeq（完整调用日志，校验 S-OS-11 顺序）
       · checkpoints（WdgM seId 序列）
       · terminateCount / startSchedCount / idleMapCalls
```

Idle 任务的 `for(;;)` 死循环经 harness 内 `setjmp`/`longjmp`：`Os_TaskMap` mock
在累计 `idleIters` 次调用后 `longjmp` 跳出，覆盖循环体且不挂起进程。与既有 ASW
E2E 一致，在原生测试框架内执行**真实生成文件**。所有外部符号均为 harness mock，
**生产代码零改动**（生成文件 `DO NOT EDIT`）。

## 输入和输出

### 输入因子

| 因子 | 含义 | 取值（等价类/边界） | 分类 |
|---|---|---|---|
| `op` | 本阶段执行动作 | `run` | When — 执行控制 |
| `task` | 驱动哪个任务体 | `1ms`/`10ms`/`50ms`/`100ms`/`5000ms`/`idle` | When — 执行目标 |
| `idleIters` | idle 死循环跳出前的 map 调用次数 | `3`（默认，覆盖循环体与 longjmp） | When — 执行控制 |

### 输出因子

| 因子 | 含义 | 关注期望值 |
|---|---|---|
| `state.callSeq[]` | 调用日志（`map:<id>`/runnable 名/`cp:<seId>`/`TerminateTask`/`StartScheduleTables`） | 与生成代码逐行对应 |
| `state.checkpoints[]` | WdgM checkpoint 的 seId 序列 | 10ms=`[2,0,1,4]`、50ms=`[3]` |
| `state.terminateCount` | `TerminateTask` 调用次数 | 周期任务=1、idle=0 |
| `state.startSchedCount` | `Cvc_Os_StartScheduleTables` 调用次数 | idle=1 |
| `state.idleMapCalls` | idle 循环内 map 调用次数 | =idleIters |

## 代码路径覆盖

本模块是**真实可执行代码**（首个进入覆盖率报告并带逐行数据的生成文件），执行
覆盖率口径与既有 ASW E2E 一致：

- **全部 6 个函数**：1ms/10ms/50ms/100ms/5000ms/Idle 各有一个场景驱动，函数覆盖 100%。
- **全部 41 行可执行行**：每个任务体的调用语句都被对应场景命中；Idle 的
  `for(;;)` 与循环内 map 调用被 `idleIters=3` 的循环体命中（9 次 = 3 场景 × 3 迭代）。
- **WdgM checkpoint 位置**：`callSeq` 断言 checkpoint 紧跟在对应 runnable 之后
  （10ms 的 cp:2 在 EStop 后、cp:0 在 Pedal 后、cp:1 在 VSM 后、cp:4 在 Dashboard 后），
  证明生成器把 checkpoint 精确复刻在首个子实体后。

## 无法覆盖的代码说明

> 本模块**无**无法覆盖的可执行代码：**41/41 行、6/6 函数、13/13 区域全部被
> 端到端测试覆盖**。

- `Rte_TaskBodies_Cvc.c` 不含 `#ifdef PLATFORM_HIL/SIL_DIAG/UNIT_TEST` 分支，
  无编译期排除项；六个任务体均为顺序调用（无判断点），分支覆盖不适用。
- Idle 任务的 `for(;;)` 正常语义永不返回；harness 用 `setjmp`/`longjmp` 在
  `idleIters` 次后跳出以覆盖循环体，属于测试专用机制（仅存在于 harness，生产
  代码不变）。
- 未链接任何 BSW 服务逻辑（`WdgM`/`Com`/`Can`/SWC 均为 mock），因此 harness
  mock 文件的覆盖率被 `_generate_coverage_html` 的 `/app/fault_inject/.*` 忽略，
  与既有 ASW harness 一致；报告只展示生成文件 `Rte_TaskBodies_Cvc.c` 本身。
