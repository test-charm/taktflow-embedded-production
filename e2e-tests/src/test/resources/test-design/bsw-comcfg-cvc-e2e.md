## 被测功能

**CVC 的 Com 层真端到端行为（生成自 DBC 的 BSW 配置 + 真实 Com 运行时）**

`firmware/ecu/cvc/cfg/Com_Cfg_Cvc.c` 由 `tools/arxmlgen` 从
`gateway/taktflow_vehicle.dbc`（→ `TaktflowSystem.arxml` → `project.yaml`）生成，
文件头为 `GENERATED BY arxmlgen v1.0.0 -- DO NOT EDIT`。它导出
`const Com_ConfigType cvc_com_config`，被 `firmware/ecu/cvc/src/main.c`
（`Com_Init(&cvc_com_config)`）在真实 ECU 中运行时消费。生成配置的核心事实：

- **TX PDU 表**：12 项 `Com_TxPduConfigType`（PduId/Dlc/CycleTimeMs/TxMode/
  E2eProtected/E2eDataId/E2eCounterBit/E2eCrcBit）。
- **RX PDU 表**：33 项 `Com_RxPduConfigType`（PduId/Dlc/TimeoutMs/E2eProtected/
  E2eDataId/E2eMaxDelta/E2eDemEventId/E2eSmWindowValid/E2eSmWindowInvalid/
  CommStatusRteSignalId）。
- **TX 信号表**：58 项、**RX 信号表**：124 项 `Com_SignalConfigType`
  （BitPosition/BitSize/Type/ShadowBuffer/RteSignalId…）。
- 汇总：`mainFunctionPeriodMs = 10`。

本测试以**真端到端**方式验证这些配置的**运行时后果**（不再读回数据表本身）：
在被测系统上运行**插桩的真实 CVC SIL ECU**（`LLVM_COV=1` 构建，见
`docker/Dockerfile.vecu`），通过 `bus-probe` 观测其在 vcan0 上**真实发出的帧**，
逐项与 DBC 唯一真源比对——DLC、周期（DBC GenMsgCycleTime）、E2E 头（DataId/
Alive/CRC）。配置一旦与 DBC 脱节（DLC 错、周期错、E2E DataId 错、位布局错），
总线帧必然不达标。

覆盖链路（全真实，无 mock）：

```text
当POST /api/test/bsw/comcfg/cvc {op: bus-probe, targets: [...]}
  →（被测系统）[10ms 任务 → Com_MainFunction_Tx → PduR → CanIf → Can_Posix → vcan0]
  →（观测）python-can(socketcan)+cantools 收集真实帧
  → 与 DBC 比对：dlc/dl cOk / cycleMs/cycleOk / e2e/dataId/dataIdOk /
    aliveMonotonic / crcValid / decoded
```

生产代码零改动；被测系统=真实 ECU 二进制，BSW 覆盖（Com/E2E/PduR/CanIf/MCAL）
由总线测试自身产生（`/cov` .profraw → 网关 `_collect_ecu_coverage_info`）。


## 被测代码流程图

### 总线观测（bus-probe，当前 feature 路径）

```text
[当POST /api/test/bsw/comcfg/cvc]
  └─ [bus-probe] → [gateway 打开 vcan0(socketcan)]
      → 对每个 target（DBC 消息名）按 DBC GenMsgCycleTime 收集真实帧
      → [任务体 → Com_MainFunction_Tx → PduR → CanIf → Can_Posix → vcan0]（真实 ECU）
      → 逐帧校验并返回：
           found / busUp            （帧存在性、总线可用）
           dlc / dlcOk              （帧长 vs DBC length）
           cycleMs / cycleOk        （DBC 名义周期；cycleOk=有界带宽+稳定周期性，
                                      兼容 Docker 非实时节拍）
           e2e / dataId / dataIdOk  （E2E 头：byte0 = Alive:4|DataId:4）
           aliveMonotonic           （alive 0..15 单调递增/回绕）
           crcValid                 （byte1 = CRC-8 SAE-J1850，对 payload[2:]+DataId）
           decoded                  （cantools 按 DBC 解码的信号值）
```

## 输入和输出

### 输入因子

| 因子 | 含义 | 默认 | 分类 |
|---|---|---|---|
| `op` | 本阶段动作 | `bus-probe` | When — 执行控制 |
| `targets` | 要观测的 DBC 消息名数组（`results[i]` 恒为目标） | 无（必填于场景）；服务器默认 4 个安全 TX | When — 观测目标 |
| `windowMs` | 观测窗口（毫秒） | `2000` | When — 采集时长 |
| `minFrames` | 每目标至少收集的帧数 | `5` | When — 采样量 |

### 输出因子

| 因子 | 含义 | 关注期望值 |
|---|---|---|
| `state.ecu` | 被测 ECU | `"cvc"` |
| `state.found` / `state.busUp` | 帧存在性 / 总线可用 | `true` / `true`（未知消息 → found=false busUp=true；总线不可用 → found=false busUp=false） |
| `state.dlc` / `state.dlcOk` | 观测帧长 vs DBC length | CVC_Heartbeat `4`、Vehicle_State `6`、Torque_Request/Steer_Command `8`、Body_Control_Cmd `4`；`dlcOk=true` |
| `state.cycleMs` / `state.cycleOk` | DBC 名义周期；`cycleOk`=有界带宽+稳定周期性 | Heartbeat `50`、其余 `10`、Body `100`；`cycleOk=true` |
| `state.e2e` / `state.dataId` / `state.dataIdOk` | E2E 保护与 DataId | Heartbeat `2`、VS `5`、Torque `6`、Steer `7`；Body 无 E2E（`e2e=false`） |
| `state.aliveMonotonic` / `state.crcValid` | alive 单调 / CRC-8 校验 | `true` / `true` |

> 期望值直接由 `gateway/taktflow_vehicle.dbc` 派生：BO_ DLC、`GenMsgCycleTime`
> 属性、`E2E_DataID` 属性与 DBC 信号布局，即「DBC 是唯一真源」。

## 代码路径覆盖

本测试被测系统是**真实 ECU 二进制**，覆盖口径为「总线测试执行期间真实 CVC 运行
代码的行覆盖」（chore：插桩 ECU 周期 flush `.profraw` 到 `/cov`，网关
`_collect_ecu_coverage_info` 合并进报告，对 BSW 不做 ignore）。覆盖对象是
Com 层的真实运行时代码，而非数据表：

- 真实链路各层均在总线测试中出现逐行覆盖：`bsw/services/Com/src/Com.c`、
  `bsw/services/E2E/src/E2E.c`、`E2E_Sm.c`、`bsw/ecual/PduR`、`bsw/ecual/CanIf`、
  `bsw/mcal/Can`（+其它 MCAL）、`bsw/rte/Rte.c`、`bsw/os/bootstrap/*`、
  `platform/posix/src/Can_Posix.c` 等。
- 生成配置 `Com_Cfg_Cvc.c` 为**纯数据表**（编译期常量、零可执行行），clang
  插桩不产生任何区间 → **不进 lcov 报告**（`app.py` 中注有原因）。其一致性以
  **数据表访问口径**间接保证：bus-probe 观测到的帧 DLC/周期/E2E 头全部来自该
  配置的真实消费——任一配置条目与 DBC 脱节都会导致帧属性断言失败。

| 层次 | 报告中的覆盖来源 | 口径 |
|---|---|---|
| Com/E2E/PduR/CanIf/MCAL/RTE/OS（真实运行时） | bus-probe 执行期间真实 CVC 的 .profraw | 逐行/函数/区域覆盖 |
| `Com_Cfg_Cvc.c`（生成数据表） | —（无可执行代码） | 数据表访问口径（帧属性=DBC） |

## 无法覆盖的代码说明

### 当前真端到端下的不可观测面

- **生成配置 `Com_Cfg_Cvc.c` 不产生行覆盖**（无函数可插桩），这是固有口径；
  其一致性由 bus-probe 观测的真实帧属性（DLC/周期/E2E 头）间接保证。
- **节拍非实时**：Docker 下真实帧 cadence 约为 DBC 名义的 3x，`cycleOk` 采用
  有界带宽+稳定周期性判定，覆盖该差异仍能抓无帧/burst/重复发射；精确周期
  达标由 HIL（RT Linux）负责。
- **可达帧依赖栈状态**：E-Stop 帧仅锁存时出现，故由 `bsw_rtetaskbodies` 的
  `ftti` 断言；bus-probe 只断言常态在线的安全 TX 帧。

### 生产代码与报告口径

- **被测系统是真实 ECU 二进制**，非 harness：`Com_Cfg_Cvc.c`
  `const Com_ConfigType cvc_com_config` 由真实 `main.c` 消费，无任何测试专用
  修改/UNIT_TEST getter。
- **SIL 插桩基础设施（模拟专用，非物理 ECU 构建）**：`Makefile.posix`
  `LLVM_COV=1`（clang `-fprofile-instr-generate`）、`platform/posix/src/
  Sil_Coverage.c`（周期 `__llvm_profile_write_file`）、`Dockerfile.vecu`
  （Debian trixie + clang19，与网关同版本）、compose 共享 `cov` 卷与
  `LLVM_PROFILE_FILE`。这些仅存在于 SIL 构建路径 / 平台 POSIX 层。
- **覆盖率回收**：网关 `_collect_ecu_coverage_info` 合并 `/cov/cvc_*.profraw`
  + docker 取回插桩二进制 + `llvm-cov export`（**对 `/app/firmware/bsw` 不
  ignore**）→ 报告展示真实 BSW 模块覆盖（Com/E2E/PduR/CanIf/MCAL/RTE/OS）。
