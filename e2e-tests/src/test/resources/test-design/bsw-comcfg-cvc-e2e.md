# CVC Com 配置一致性 (bsw_comcfg_cvc) E2E 测试设计

## 被测功能

**CVC 的 Com 模块配置（生成自 DBC 的 BSW 配置数据表）**

`firmware/ecu/cvc/cfg/Com_Cfg_Cvc.c` 由 `tools/arxmlgen` 从
`gateway/taktflow_vehicle.dbc`（→ `TaktflowSystem.arxml` → `project.yaml`）生成，
文件头为 `GENERATED BY arxmlgen v1.0.0 -- DO NOT EDIT`。它导出
`const Com_ConfigType cvc_com_config`，被 `firmware/ecu/cvc/src/main.c`
（`Com_Init(&cvc_com_config)`）在运行时消费。本测试对生成的**数据表本身**做
DBC 一致性读回与结构不变量检查：

- **TX PDU 表**：12 项 `Com_TxPduConfigType`（PduId/Dlc/CycleTimeMs/TxMode/
  E2eProtected/E2eDataId/E2eCounterBit/E2eCrcBit）。
- **RX PDU 表**：33 项 `Com_RxPduConfigType`（PduId/Dlc/TimeoutMs/E2eProtected/
  E2eDataId/E2eMaxDelta/E2eDemEventId/E2eSmWindowValid/E2eSmWindowInvalid/
  CommStatusRteSignalId）。
- **TX 信号表**：58 项 `Com_SignalConfigType`（SignalId/BitPosition/BitSize/Type/
  PduId/ShadowBuffer/RteSignalId/UpdateBitPos）。
- **RX 信号表**：124 项（同上）。
- 汇总：`mainFunctionPeriodMs = 10`。

覆盖链路：

```text
测试 API 注入（op=dump / op=txpdu id=N / op=rxpdu id=N /
              op=sig table=tx|rx id=N / op=invariants）
  → harness 链接 Com_Cfg_Cvc.c，读回 extern const Com_ConfigType cvc_com_config
  → 按 op 格式化 JSON：
       dump       → 计数汇总（txPduCount/rxPduCount/txSignalCount/rxSignalCount/mainPeriodMs）
       txpdu id=N → 该 PDU 的 DLC/周期/模式/E2E DataId/counterBit/crcBit
       rxpdu id=N → 该 PDU 的 DLC/超时/E2E DataId/MaxDelta/Dem事件/SM窗口/通信状态绑定
       sig id=N   → 该信号的 bitPos/bitSize/type/pduId/rteSignalId/updateBitPos
       invariants → 结构检查结果（txIdsUnique/rxIdsUnique/signalsFitInDlc/
                     e2eLayoutOk/shadowBuffersNonNull/allPass）
```

与既有 ASW E2E 一致，通过测试专用 API 在原生测试框架内读取**真实生成文件**。
本模块为纯 `static const` 数据表，harness 只读不写，**生产代码零改动、无
UNIT_TEST 观测 getter**（`cvc_com_config` 的表格指针全部指向生成文件内静态数组，
harness 经公开结构体直接遍历）。

## 被测代码流程图

### 数据表访问（harness）

```text
[op 分发]
  ├─ dump → [读 cfg->txPduCount/rxPduCount/txSignalCount/rxSignalCount/mainFunctionPeriodMs]
  ├─ txpdu → [遍历 cfg->txPduConfig 按 PduId 匹配] → [输出 DLC/周期/模式/E2E 字段]
  ├─ rxpdu → [遍历 cfg->rxPduConfig 按 PduId 匹配] → [输出 DLC/超时/E2E 字段]
  ├─ sig   → [遍历 cfg->txSignalConfig|rxSignalConfig 按 SignalId 匹配] → [输出位定义]
  └─ invariants → [五项结构检查] → [输出 allPass]
```

## 输入和输出

### 输入因子

| 因子 | 含义 | 取值（等价类/边界） | 分类 |
|---|---|---|---|
| `op` | 本阶段读回动作 | `dump` / `txpdu` / `rxpdu` / `sig` / `invariants` | When — 执行控制 |
| `id` | `txpdu`/`rxpdu`/`sig` 查询的 PDU/信号 ID | TX PDU `0..11`、RX PDU `0..32`、信号 `0..123` | When — 查询目标 |
| `table` | `sig` 查询的信号表 | `tx` / `rx` | When — 查询目标 |

### 输出因子

| 因子 | 含义 | 关注期望值 |
|---|---|---|
| `state.ecu` | 编译期 ECU 标识 | `"cvc"` |
| `state.txPduCount` / `rxPduCount` | 配置规模 | `12` / `33` |
| `state.txSignalCount` / `rxSignalCount` | 配置规模 | `58` / `124` |
| `state.mainPeriodMs` | Com 主函数周期 | `10` |
| `txpdu: dlc/cycleMs/mode/e2e/dataId/counterBit/crcBit` | TX PDU 字段 | 按 DBC 派生值 |
| `rxpdu: dlc/timeoutMs/e2e/dataId/maxDelta/demEvt/smValid/smInvalid/commStatusSigId` | RX PDU 字段 | 按 DBC 派生值 |
| `sig: bitPos/bitSize/type/pduId/rteSignalId/updateBitPos` | 信号位定义 | 按 DBC 派生值 |
| `invariants: txIdsUnique/rxIdsUnique/signalsFitInDlc/e2eLayoutOk/shadowBuffersNonNull/allPass` | 结构检查 | 全 `true` |

> PDU/Signal ID 采用 `Cvc_Cfg.h` 中的宏数值（如 `CVC_COM_TX_VEHICLE_STATE=2`、
> `CVC_COM_TX_TORQUE_REQUEST=3`、`CVC_COM_RX_FZC_HEARTBEAT=0`、
> `CVC_COM_RX_LIDAR_DISTANCE=10`），期望值直接由 `Com_Cfg_Cvc.c` 注释中的
> CAN ID（0x001/0x010/0x100/0x101/0x011/0x012/0x013…）与 DBC 周期注释交叉确认。

## 代码路径覆盖

本模块是**数据表而非函数**，覆盖率口径为「harness 对生成文件 `Com_Cfg_Cvc.c`
的访问/遍历覆盖」：

- 全部 12 项 TX PDU：`tx_estop_broadcast`/`tx_cvc_heartbeat`/`tx_vehicle_state`/
  `tx_torque_request`/`tx_steer_command`/`tx_body_control_cmd`/`tx_dtc_broadcast`/
  `tx_fzc_virtual_sensors` 直接查询；`invariants_all_pass` 的
  `txIdsUnique`/`signalsFitInDlc`/`e2eLayoutOk` 遍历剩余项（XCP/虚拟传感器/UDS）。
- 全部 33 项 RX PDU：`rx_*` 用例直接查询关键项；`invariants_all_pass` 遍历
  其余（SC 状态/ICU/TCU/BCM 心跳、制动故障、电机切断、电流/温度、灯光/指示器/
  门锁、XCP/UDS 通道）。
- TX 信号表：直接查询 9 个信号（torque×5、vsm×2、e2e dataid、xcp uint32）；
  `signalsFitInDlc`/`e2eLayoutOk` 遍历全部 58 项。
- RX 信号表：直接查询 3 个信号（fzc ecuid、sc alive、越界 999）；不变量遍历
  全部 124 项。
- `mainFunctionPeriodMs` 经 `dump_summary` 断言。
- harness 执行路径：越界查询场景覆盖 `find_*` 的 NULL 返回与 `format_*` 的
  `found=false` 分支；`type_uint32` 场景覆盖 `com_type_name` 的 UINT32 分支。
